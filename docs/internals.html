Current technical notes

Checked 2026-09-25. This page describes the current Rareities/CloudBridge source snapshot. It is not a release-readiness claim.

No fork release is published. GitHub currently shows no Actions runs, open PRs, or releases for the Rareities repositories. The checked-in CI builds/tests OSS debug only and does not upload artifacts or publish releases. Recheck live GitHub status before relying on this snapshot.

Use the repository-root build guide, Windows build guide, security policy, and requirements matrix as the current written references.

1. Project architecture

ModulePurpose
appAndroid app, UI, profiles, services, and background work.
rcloneBuilds rclone executable binaries for Android ABIs. The app launches the packaged executable with Runtime.exec; this is a subprocess boundary, not JNI loading.
safdavBridges Android Storage Access Framework document trees to the app's WebDAV integration.

2. rclone integration

CloudBridge consumes the Rareities rclone fork. The repository URL and full immutable source SHA are configured by de.schuelken.cloudbridge.rCloneRepoUrl and de.schuelken.cloudbridge.rCloneRef in gradle.properties. The current pin is fe775a8b58cf217fdf4bd34f0975af1e4c19c1a0. Do not edit fetched/generated files under rclone/cache/; engine changes belong in the standalone rclone repository and must be tested independently before app integration.

3. Configuration and credentials

The rclone config is stored in app-private storage and can contain provider credentials. The app does not encrypt the entire file at rest; rclone's per-value obscure is reversible. When an rclone config passphrase is stored, its ciphertext is wrapped with Android Keystore AES-GCM, which protects that passphrase only. Android backup is disabled in the manifest; this is not encryption. See ADR-001 and SECURITY.md.

4. Local build and tests

Check the versions in gradle.properties. The current setup uses JDK 17 for CI, Go 1.26.0 or newer, Android API 36, and the pinned NDK. Git HTTPS access and uncached dependency downloads may be required.

./gradlew :app:testOssDebugUnitTest :app:assembleOssDebug
# Windows PowerShell:
.\gradlew.bat :app:testOssDebugUnitTest :app:assembleOssDebug

A full app build checks out and compiles the pinned rclone source. Excluding native checkout/build tasks is suitable only for an isolated app-JVM diagnostic; it is not native integration or complete APK evidence. See the root build guides for environment details.

5. CI, signing, and release

.github/workflows/android.yml runs on pushes and pull requests targeting master and supports manual dispatch. It runs :app:testOssDebugUnitTest and :app:assembleOssDebug. It does not upload an APK artifact, build a release, or publish to Google Play.

Release packaging/signing tasks require a readable production keystore and all four configured signing values. They fail closed and never fall back to the debug key. No release workflow is currently authorized by this documentation. Certificate continuity, migration/rollback, provenance, security, device, and provider acceptance are mandatory before distribution.

Version defaults and ABI version offsets are set in app/build.gradle. No automatic commit-count beta version or release publishing is configured in the current Android workflow.

6. Storage Access Framework

The safdav module is present for access to Android document trees granted by the user. A document-tree grant is sensitive: only grant it to trusted apps and test against disposable data. Provider lifecycle and device-specific behavior still require the handoff's acceptance tests.

7. External automation compatibility

The legacy README recipe directly starts Services.SyncService, but the manifest declares that service exported=false. That direct cross-app call is not currently supported. Do not configure another app to invoke it; the secure external automation contract remains a feature-survival audit item.

8. Bisync safety status

Preview only: safe Bisync initialization, apply, and recovery are not available in this fork. Do not use this build for two-way Bisync mutations or interpret a preview report as authorization to mutate either endpoint. Keep important data backed up independently until the app-owned preservation and restore gates have been completed and accepted.

9. Acceptance boundary

JVM tests, a compile, an emulator, or a debug APK do not establish device/provider acceptance. The master handoff requires a Galaxy S26 on One UI 8.5/9 with the actual Android API level and firmware recorded, plus a separately verified disposable Proton test scope. If unavailable, report NOT RUN.
