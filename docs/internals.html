How ProtonBridge works

ProtonBridge is an Android rclone file manager focused on Proton Drive folder bisync. It descends from CloudBridge, Round Sync, RCX and rcloneExplorer. The consolidated changelog contains commit history, usage, security and validation limits.

Architecture and native engine

The app module uses Java/Kotlin under io.github.rareities.protonbridge. The rclone module builds a native PIE executable named librclone.so, launched as a child process; it is not a JNI shared library. Local authenticated remote-control services support browsing and streaming. The safdav module bridges user-granted document trees to local WebDAV.

Engine source is pinned with io.github.rareities.protonbridge.rCloneRepoUrl and rCloneRef in gradle.properties, currently from Rareities/rclone. Updates require reviewing and changing the exact commit, not following a moving branch.

Build and release

Use JDK 17, Android SDK 36 and the Go/NDK versions pinned in gradle.properties. Set sdk.dir in local.properties or ANDROID_HOME.

git clone https://github.com/Rareities/ProtonBridge.git
cd ProtonBridge
./gradlew assembleOssDebug
./gradlew testOssDebugUnitTest lint -x :rclone:buildAll

Native builds use CGO/bionic DNS and 16 KiB ELF alignment. First builds fetch the reviewed source and build all ABIs. Debug builds append .debug to the application ID.

Versioning and signing

Version names and base codes are checked into gradle.properties. Base codes end in zero; the final digit is reserved for ABI offsets. New release codes must exceed all previously published APK codes.

Verified release workflow

The explicit fork-release.yml workflow runs only from master. It validates the matching consolidated changelog section, builds pinned engines, runs tests and lint, signs five APKs using protected environment secrets, and verifies identity, certificate and native provenance. Publication uses verified assets and checksum metadata. This fork does not publish automatically on every push or publish to Google Play.

Update checks

Optional update checks query this fork's GitHub releases and display a notification linking to the release. They do not silently install APKs and require battery not low.

Storage access

Document-tree access is granted through Android's picker. Storage permissions, provider grants and cloud credentials must remain valid for scheduled work. Bisync requires preview and explicit baseline approval; see the consolidated usage guidance before syncing important data.
