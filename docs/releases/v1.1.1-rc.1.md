# CloudBridge 1.1.1-rc.1 — safety follow-up

Signed prerelease from `master`, following 1.1.0-rc.1. Retains the pinned rclone engine
`47048daf3c80e1de633ec9a1f09981f4c30f9a30`; no engine source patch is needed for
these managed-app fixes.

- Serialize bisync configuration/account validation and actual native launch.
  Remote edits and new RC jobs cannot interleave that preparation interval;
  native ownership continues protecting the running child after launch.
- Persist a local configuration generation before manual edits, reconnects,
  deletes, renames and imports. OAuth account replacement now retires old
  approval, even when only token fields change. Automatic refresh does not.
  The generation is excluded from backups and rollback snapshots.
- Resolve transfer defaults once into a full task snapshot, used by both
  approval fingerprint and command construction. The editor uses the same rule.
- Commit restore rollback files, pending marker and directory entries before
  replacing live components; use SQLite FULL synchronization and installed-file
  barriers. Durably retire the pending marker before deleting rollback snapshots.
- Move to approval policy v4. Existing approvals require a fresh preview and
  reviewed initialization; no automatic resync or baseline deletion is added.
- Bump versionName and ABI-safe base versionCode together to 1.1.1-rc.1 / 110.
  Validate tags, checked-in versions and prior ABI codes before signing.
- Validate readiness before resolving a baseline UUID. Run before initialization
  now explains Preview → review → Initialise instead of exposing a UUID parse
  error. Reject malformed baselines and repair task identity on explicit save.
- Simplify the bisync editor: keep Preview and Review/initialise visible and
  collapse optional tools under Advanced. Preserve saved settings.
- Allow opening a completed preview for review without waiting on a separate
  background check; validate fingerprints before approval and native launch.
- Show execution phases, elapsed time and persistent queued waiting reasons.
  Bound foreground startup and local flag checks; retain normal transfer duration.
- Add fork ancestry, project purpose, AI-development disclaimer and the complete
  commit-linked changelog at the top of README without removing original content.

Validation results and remaining device/live-account limits are recorded in
[FORK_CHANGELOG.md](../FORK_CHANGELOG.md). Host verification passed: 176 tests,
lint, five debug APK builds, instrumentation compilation and independent source
review. CI rebuilds and verifies the signed release distribution separately.
The user reported that the debug test build works correctly on their device.
This is user-reported acceptance, not an independently executed device or
live-account compatibility matrix. The signed release is rebuilt and verified
separately. Existing
bisync approvals need a fresh preview and reviewed initialization under policy v4.

Release APKs use the normal application ID and approved signing certificate;
unlike the earlier debug builds, they update the release installation. Version
codes exceed all previous ABI variants. GitHub publication marks this as a
prerelease and does not promote it as the latest stable release.


## Promotion audit and cleanup

The aggregate changes since 1.1.0-rc.1 were reviewed again before promotion.
No new concrete app blocker was found; approval/account binding, process ownership,
restore durability, UUID readiness and saved Advanced options remain protected.
Temporary debug-prerelease publication and test-branch signing exceptions were
removed. Debug APK builds are manual; host checks and dependency auditing remain
in CI. Superseded test branches and Actions artifacts are retired after successful
signed release verification. Old release assets and commit history are retained
for rollback and provenance; unmerged obsolete branch history is archived before
its branch is removed.
