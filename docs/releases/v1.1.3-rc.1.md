# ProtonBridge 1.1.3-rc.1 — battery and privacy optimizations

Same application ID `io.github.rareities.protonbridge` and fork signing
certificate as 1.1.2-rc.1; base versionCode 130. No configuration migration or
automatic baseline reset is performed. The reviewed rclone engine stays pinned
to `de1b01ca4ca02488ef2942ea6f2f00c0a35dc08e`.

- Remove forced high-performance Wi-Fi locks and duplicate worker CPU locks;
  keep foreground WorkManager ownership and service/RC locks for active work.
- Replace ten-per-second exit inspection with a blocking exit waiter and timed
  cancellation/deadline checks. Reduce native stats and progress updates to
  five seconds, quiet heartbeat to fifteen seconds and RC polling to three.
- Make battery exemption optional; new idle scheduling defaults defer wakeups.
  Existing saved schedule/permission choices are preserved.
- Bound/cancel optional health probes and local config reads, drain both pipes,
  avoid false reconnect alarms from quota/permission errors and private logging.
- Fix thumbnail-server pipe draining/cancellation. Harden local Markdown against
  embedded network loads, JavaScript, file/content access and custom schemes;
  clean up its executor with the host activity.
- Require battery not low for optional update checks and confirm foreground
  service startup before native file transfers begin.

Bisync approval, checksum/cryptographic verification, actual-exit leases and
baseline recovery remain intact. Existing Android Unrestricted battery mode
cannot be changed by the app: choose Optimized in Android settings and turn off
allow-while-idle scheduling if delayed starts are acceptable.

No device battery or live-Proton performance measurement was performed; there
is no claimed percentage saving. Progress/RC status updates may appear a few
seconds later while completion and cancellation remain explicit.
