# ProtonBridge 1.1.2-rc.1 — new identity and Proton listing performance

Signed prerelease following 1.1.1-rc.1, introducing the separate application ID `io.github.rareities.protonbridge`
with the existing fork signing certificate and base versionCode 120.

- Pin rclone to reviewed engine commit
  [`de1b01ca4`](https://github.com/Rareities/rclone/commit/de1b01ca4ca02488ef2942ea6f2f00c0a35dc08e).
- Resolve a listed folder's verified parent key once instead of repeatedly
  fetching/decrypting the ancestor chain for every file. This reduces work
  during scans before transfers begin, including bisync scans with caching off.
- Keep fresh listings, authenticated names/node keys/revision attributes,
  duplicate detection and unknown-plaintext-size handling. No stale metadata
  cache, automatic baseline reset or relaxed checksum policy is introduced.
- Add signed/encrypted regression fixtures, cancellation/concurrency checks and
  a deterministic token-refresh test fixture.

A 20-file localhost benchmark reduced ancestor GETs from 42 to 2 (95.2%) and
scan time from 2.047 seconds to 0.712 seconds (~2.9×). These are host fixture
results, not measured Android/live-Proton throughput. The user's reported
small-file upload slowdown may have additional causes; per-file API/crypto and
filename-search overhead remain subjects for profiling.

Engine backend, bridge, authentication and bisync tests passed under the race
detector, a host CLI built successfully, and independent review passed. The
release pipeline separately builds all four Android engines, runs app unit
checks/lint, signs five APKs and verifies signatures/native payload provenance.
Local Android validation passed all 176 app tests with no failures or skips, lint,
and instrumentation-test compilation. No independent device or live-account
performance test was run for this version.

If an existing task's approval is retired after upgrading, perform a fresh
Preview → review → Initialise. Approval checks remain required; the update does
not initialize or delete baselines automatically.

See the [full changelog](https://github.com/Rareities/ProtonBridge/blob/master/docs/FORK_CHANGELOG.md) and
[engine performance investigation](https://github.com/Rareities/rclone/blob/de1b01ca4ca02488ef2942ea6f2f00c0a35dc08e/docs/FORK_PERFORMANCE.md).

## New fork identity

The repository and app are now ProtonBridge. Java/Kotlin packages, Android
namespace/application ID, provider authorities, updater and issue links, APK
names, launcher/adaptive/themed/splash icons and debug branding are aligned.
Startup and About explain the Proton Drive/bisync purpose, ancestry, unofficial
status and AI-development/use-at-own-risk disclaimer. The original upstream
README remains under a labeled historical section.

**This installs separately from CloudBridge**, rather than updating it. Export
configuration using the old app’s backup tools, then import it in ProtonBridge
if needed. Grant the new app’s permissions and review/initialize its bisync tasks.
Stop old schedules before enabling matching schedules in ProtonBridge.
