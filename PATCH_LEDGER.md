## 2026-09-27 - WP03 config-file rollback and credential commit hardening

- **Uncommitted change:** `ConfigFileRestorer` uses Android `AtomicFile` for staged config replacement, rollback and reset deletion, attempts recovery before config reads/native launches, bounds copied bytes, and records whether a failed replacement restored the exact pre-write bytes. `Rclone` keeps the mutation barrier pending when that state is uncertain. ZIP rollback hands off the secret-generation token before revision finalization and tries credential restoration independently of a revision-finalization failure.
- **Credential failure handling:** config-secret invalidation now returns its opaque preimage through a typed failure when `SharedPreferences.commit()` reports false. The owner attempts a generation-checked restoration; a false restoration commit is never treated as durable success even when the test proxy mutates its in-memory map. This fails closed.
- **Evidence:** JDK 8/JUnit 4.13.2 standalone **21/21 PASS** (file replacement seam 4, secret-store 14, rollback coordinator 3); scoped diff check **PASS**. Full Gradle app compilation **NOT PASSED before app-source compilation** due transformed AndroidX JAR `AccessDeniedException`. The fake AtomicFile port is not Android framework or crash testing.
- **Remaining:** no durable encrypted journal before SQLite/preferences/config mutations; no startup/process-death recovery; incomplete direct/ZIP/reset and key-loss fault matrix; current Android integration and device/provider tests are **NOT RUN**. WP03 remains partial, not accepted. Do not promote this slice or release without the full handoff gates.
- **Reset follow-up:** reset now raises the revision barrier before invalidating credentials; conditional in-process restoration is permitted only when config exists and the AtomicFile backup is absent. A process-local recovery-required latch prevents uncertain preference finalization from exposing a stable revision. Focused helper suite **29/29 PASS** (JDK 17 targeting Java 8); scoped diff check **PASS**. Gradle still fails before app source on transformed AndroidX archive access. No durable multi-store journal or process-death reconciliation exists, so this remains partial.
- **Next journal boundary:** ZIP import source URI is currently read more than once, and exported JSON omits DB state affected by import (notably profiles/runs). Stage one bounded immutable archive, then persist a durable encrypted journal containing exact DB/preferences/config/secret preimages before the first mutation. Recovery must precede early providers and scheduler work. Journal key loss must preserve evidence and fail closed. Proposed byte caps are not accepted until validated. Reset and `clearApplicationUserData()` require a separate terminal-reset policy.
